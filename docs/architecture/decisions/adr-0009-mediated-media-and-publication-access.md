# ADR-0009 - Mediated media and publication access

**Status:** Accepted; protected ranges, SHA-bound resume and approved hosted CSP configuration applied; effective non-admin verification pending
**Date:** 2026-09-22
**Last updated:** 2026-09-22

## Context

Dataverse reports no custom processing-step support for InitializeFileBlocksUpload, UploadBlock, CommitFileBlocksUpload or DeleteFile. Ordinary metadata guards cannot make direct file writes safe. Existing child relationships do not cascade sharing. Contributors must not mutate a file after submission or retain a reusable upload token.

## Decision

- Add private, organization-owned `nx_uploadsession` with typed caller/parent/target identifiers, file metadata, byte/block counters, expiry, completion and continuation-token fields. Never grant application roles access or return tokens to clients. It is not a draft/history table; bytes remain in native File/Image storage.
- Own gallery and attachment rows through an empty **PRISMA Media Custodian** owner team with only Basic media Read privileges. Never add members. Mutations use synchronous APIs and system service only after caller ownership, Draft state and exact version checks.
- Use sequential blocks, two-hour unfinished-session expiry, one unfinished upload per draft, and explicit removal. Legacy clients/sessions retain 512 KiB blocks and full snapshots. New reads advertise `uploadProtocol: 2`; opted-in Begin calls suffix the kind with `:v2` and create a private `nx_name` marker, `PRISMA upload v2 `, fixing that session to 2 MiB blocks. Block replies then contain only parent/version, session, block size and confirmed byte/block counters. Clients validate exact identity, advanced version and sequential progress before merging into their existing snapshot. Begin/finalization still return full snapshots. No parallel writes, token exposure, new API parameter or schema change is needed. Every mutation advances the parent version and clears acknowledgment/clearance. Finalization checks size and shares the record read-only with its contributor owner. Finalized file bytes are immutable except mediated removal while Draft.
- Additionally advertise `maxBlockSize: 4194304` without changing `uploadProtocol: 2`, so existing clients continue parsing responses. New clients select `:v3` only when this capability is present; the private `PRISMA upload v3 ` marker fixes new sessions to 4 MiB. Existing 512 KiB/2 MiB sessions keep their original sizes. Reject mismatched negotiation or mid-upload size changes; never retry an ambiguous request with a smaller block. The 4 MiB binary payload expands to about 5.33 MiB in base64 and has passed the mediated Local Play route. Retain only aggregate last-upload phase timings in client module memory, with no identifiers, filenames, tokens, persistent storage or telemetry export.
- Store one optional dedicated thumbnail as a team-owned `nx_solutionimage` with private session kind `thumbnail`, separate from the one-to-six gallery images. Use the existing image column, caption and sort-order fields; no additional table or column is required. Never trust the legacy parent image. Thumbnail removal/replacement uses the same version-checked media protocol.
- Allow owner-only Draft metadata edits through `nx_TransitionSubmission` action `media`; its `Comments` argument carries a validated JSON array of target ID, caption (up to 200 characters) and sort order (0-12), not review feedback. Only completed targets belonging to that draft may be edited. Advance the parent version, clear acknowledgment/clearance and preserve review fields transactionally. Reject direct metadata writes. Published projections return only completed protected media and saved metadata.
- Allow owner-only Draft linked-asset create/update through the same transition API, action `asset`. Validate name (100), hint (200), HTTPS URL (2000, no credentials/whitespace), supported type and hosted-web-only embedding. Desktop/script entries require arrangements and have no URL or embedding. Existing `nx_demoasset` fields hold the content; no new tables, fields or API registrations are needed. Unknown payload properties and attempts to edit another draft's asset are rejected.
- Linked assets use team-owned attachment rows and a completed, zero-byte private lifecycle record in `nx_uploadsession`, marked with MIME `application/vnd.prisma.link`, no file token and no file upload. The returned `linkedAsset` contains the type-specific fields. This reuses the existing six-attachment limit, readonly owner sharing, review, publication sharing/revocation and controlled cleanup. File APIs cannot append blocks to completed link records, and linked records cannot be edited through file upload. External application access remains controlled by that application: revoking PRISMA shares cannot revoke an external URL already known to a user.
- Hosted linked previews omit `allow-same-origin`, use `no-referrer`, and provide a pop-out fallback. Some applications will refuse framing or need authentication/storage unavailable in that sandbox; Power Apps and Power BI always open in a new tab. Desktop guidance sends no notification or demo request. Link URLs and notes must be client-safe and contain no tokens/secrets because approved readers and present-mode viewers may see them.
- Owner deletion uses the controlled transition in ADR-0008 to revoke publication access and remove finalized/unfinished media and private sessions with their parent; shared reference data is retained.
- File bytes are not transactional with Dataverse rows: ambiguous requests require reopen and inspection, not blind replay. New video sessions use `nx_BeginResumableUpload` to store a private lowercase SHA-256 digest in `nx_sha256`; `nx_GetUploadCheckpoint` validates owner, Draft/version, exact name/size/digest, expiry and counters before returning the next confirmed block. Resume overwrites no confirmed blocks and never recompresses the reselected file. Legacy sessions without a digest and expired sessions require removal/restart. Expiry rejects writes but does not reclaim storage; automatic cleanup remains future work.
- `nx_ReadVideoRange` returns at most 1 MiB per request, with parent/media version identity and no continuation token. Each call validates parent state and requested `submission`, `published` or `present` mode, target membership and completion; native download initialization/blocks execute as the caller. Parent/media versions and access are checked again before response. Present mode requires publication and both safety flags even for owners/librarians. The client validates identity/range/version and clears playback on access/version failure; a 30-second check also covers paused or already-buffered playback. This cannot retract bytes already received, saved or captured.
- MP4Box fragments regular MP4 tracks for MediaSource with sequential reads, approximately 30 seconds ahead, eviction behind 60 seconds, a 32 MiB pending-segment ceiling and 16 MiB pre-metadata-read ceiling. Fragmented files, extra tracks or unsupported codecs do not silently lose content: the UI offers explicit full-file playback with fresh access checks. Full-download WebM remains separate. No host-token extraction, public URL, CORS bypass or new external storage is introduced.
- Use the supported environment-level code-app CSP configuration for hosted media rather than converting large videos to data URLs or exposing public media. On 2026-09-22 the user approved adding only `media-src blob:`, `worker-src 'self'`, `connect-src 'self'` and `script-src 'wasm-unsafe-eval'` in Nextant Pulse. Enforcement stays enabled; other settings remain unchanged. This applies to every code app in the environment, including the PoC, and requires explicit approval in other environments. Exact settings, verification and rollback are owned by the [security model](../security-model.md#code-app-hosting-policy).
- Publish by sharing Solution, contributor and completed media rows read-only with **PRISMA Published Readers**. Revoke those shares on withdrawal/retirement. Membership is manually administered; no users are assigned by deployment. Consultant/Project access remains a prerequisite and is never expanded by these shares.
- Require the explicit **PRISMA Librarian** role, directly or through team membership, for decisions. System Administrator alone does not qualify. Librarians have Global media Read but no direct media Write through the PRISMA role; they are trusted reviewers across the lifecycle.
- Do not use the legacy parent Solution image as trusted connected media. Contributors have Solution Write for controlled APIs; the unguardable file-operation surface on that column is not a publication input. The connected gallery/viewer uses only finalized team-owned media.

## Consequences

The approved hosting-policy change was saved through the admin center and confirmed in the published PRISMA response header, without app/backend redeployment or Dataverse writes. Packaged worker/WASM compression, Blob video decoding/seeking, progressive MediaSource buffering/seeking and caption loading passed with local fixtures inside the hosted app. This is not a full hosted Dataverse upload/publication/revocation acceptance run; the hidden integrated browser paused continuous playback. See [hosted verification evidence](../../workflows/demo-assets.md#published-host-compatibility). Historical unpublished-state notes below precede the [pilot deployment](../../../app/README.md#pilot-deployment-2026-09-22).

The approved scoped `Prisma.Deploy media-transfer --execute <tested-plugin.dll>` operation added only private `nx_sha256`, published `nx_uploadsession`, updated the existing assembly and registered three APIs in Nextant Pulse. Default invocation is read-only preview; no role definitions/assignments or code app publication changed. A first live test exposed a nested Begin/write-guard mismatch; the corrected implementation reuses the internal Begin logic in the resumable transaction and passed all 46 backend tests and the same live smoke test. Digest mismatch, stale range version and draft present-mode reads were rejected; resumed file/range checksum matched. Browser SDK resume and protected seeking also passed with privileged Luis. See [measured results and gaps](../../workflows/demo-assets.md#protected-playback-and-resume). Separate non-admin and audio/caption acceptance remain required.

The separately approved 4 MiB assembly update on 2026-09-22 passed 44 backend tests. Paired 50 MiB browser-SDK uploads took 44.4s at 2 MiB and 35.2s at 4 MiB; maximum-size 500 MiB took 358.9s with 125 blocks. Both 4 MiB-protocol files matched source checksums and persisted in a subsequent submission read. Client tests (45), connected build and lint passed. Encoding consumed under 4% of elapsed time, so read-ahead was deferred; parallel writes and resumable uploads are not implemented. No schema/permissions or code-app publication changes occurred. See [benchmark scope and cleanup](../../workflows/demo-assets.md#large-video-verification).

With explicit user approval, the tested optimization was deployed to the existing Nextant Pulse assembly on 2026-09-22. A legacy HTML upload retained 512 KiB behavior; optimized 50/500 MiB uploads used 25/250 blocks, finalized, reopened and matched source checksums. All 43 backend tests passed. The connected app remains unpublished, and schema/permissions were unchanged. Timings and temporary-fixture cleanup are recorded in [large-video verification](../../workflows/demo-assets.md#large-video-verification).

HTML and PNG upload/commit/download/removal and rejection checks passed live with the privileged owner. Browser media reload, full-size image download and sandbox isolation passed. WebP is converted to PNG because native image columns do not support WebP.

Privileged live checks also passed thumbnail upload, duplicate-thumbnail rejection, caption save, stale/direct metadata rejection and deletion of finalized/unfinished media with their parent. Browser checks verified thumbnail/card rendering, caption persistence and removal. Shared drag/keyboard reorder controls now use the existing metadata action; live readback preserves screenshot/attachment order and captions and rejects stale reorder versions. No new API or backend deployment was required. Document SDK reads and download dispatch succeeded, but browser file delivery remains unverified.

The readers team has the PRISMA CSM role; members also need the intended field-security profile and app access. Mauricio was added with explicit user approval on 2026-09-22; Media Custodian remains empty. See the [pilot assignments](../security-model.md#approved-pilot-assignments). Both team records are environment-specific data, not portable solution components. Rerun scoped provisioning in another approved environment. Assignments and additive permissions require review. Privileged return/approval and explicit share grant/revocation passed; CSM effective reads/denials, separate-reviewer sessions, cross-owner denial, retirement and hosted acceptance remain gates. The connected app is not published.

The subsequent approved lifecycle fix distinguishes linked metadata from uploaded bytes during submit/approval. Linked rows undergo saved-field and zero-byte completed-session validation, never file-download initialization; uploaded files still verify stored size. All 40 backend tests pass, including a regression that asserts no download call for a valid link and rejects unsafe metadata or changed file sizes. The live [lifecycle test](../../workflows/contribution-and-review.md#verified-lifecycle) verified Read shares on solution, contributor, PNG, HTML and link targets, then zero explicit/inherited masks after withdrawal and complete fixture cleanup. Luis acted as owner and Librarian with administrator privileges, so this does not prove effective least-privilege revocation.

The user-approved linked-asset update was uploaded to existing assembly `08207a52-1ab6-f111-aaac-6045bd049fba` in verified Nextant Pulse on 2026-09-22. All 39 backend tests passed. Local Play verified create of all four types, hosted edit, readback/reopen, opaque sandbox rendering with pop-out, desktop arrangements, unsafe-URL and stale-version rejection, mediated removal and parent cleanup. Temporary draft `c4fa1064-87b6-f111-aaac-6045bd049fba` was removed, leaving three originals. External anchor targets/rel were verified, but the integrated browser emitted no popup event; signed-in Power Apps/BI launch acceptance remains open. No schema changes, user/team assignments or code-app upload occurred.
